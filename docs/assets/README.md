## 数据与脱敏 / Data and privacy

- 所有 RX 为内置模拟器产生的心跳或命令回显；`DEMO received` 不是真实 shell 结果。
- 演示仅使用 `help`、`date`、`uptime` 等公开示例命令，以及为截图新建的示例脚本。
- 未使用真实设备日志、登录凭据、网络标识、业务信息或个人用户目录；图片保留模拟设备标识，不将模拟结果伪装成实机验证。
- 没有修改应用界面或伪造回包；任务详情图片仅截取实际详情对话框。
- 应用的「隐藏输入」不会保证清除 RX 中的设备回显。将来更换为真实日志截图时，需要重新检查并脱敏。

All received data is generated by the simulator. Screenshots contain no real device logs, credentials, network identifiers, business data or personal profile paths. The task image is a crop of the actual detail dialog. Hidden input does not guarantee redaction of echoed RX data.

## 手动复现 / Reproduce manually

1. 在独立数据目录启动 `serial-workbench serve --port 8766 --data-dir <empty-demo-directory>`，打开 `http://127.0.0.1:8766`。
2. 点击「打开模拟设备」，创建包含 `date` 与 `uptime` 的共享脚本，设置 CRLF、200 ms 间隔，并等待 `OK`。
3. 网页发送 `help`，CLI 发送 `uptime`，MCP 使用 `serial_script_run` 运行上述脚本。CLI 和 MCP 都通过 `--url http://127.0.0.1:8766` 指向这个后台。
4. 在「协作」查看三种来源的操作；暂停显示后截取概览，在「脚本」截取脚本库，再展开脚本任务的「命令与回包」。
5. 核对图片只包含模拟会话，截图完成后停止这个独立后台。

Start a separate daemon with an empty data directory, explicitly open DEMO, create and run example scripts through the browser/CLI/MCP, then capture the overview, scripts and task dialog. Review every image before sharing and stop the isolated daemon afterward.
